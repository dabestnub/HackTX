Step 1 - Verify ASL recognition (partial; one static letter tested)
----------------------------------------------------------------------------
Repository reviewed: https://github.com/Gj-345/asl-hand-gesture-recognition

Source-confirmed facts:
- The repository includes ml/models/best_model.pth (326,197 bytes),
  ml/models/classes.pkl (120 bytes), and ml/hand_landmarker.task
  (7,819,105 bytes). Model artifacts are present in the public repository.
- app.py loads those artifacts from paths relative to the current directory;
  run it from the recognition repository root.
- app.py opens webcam device 0 via OpenCV, flips frames, detects one hand with
  MediaPipe, flattens 21 x/y/z points into 63 values, then subtracts the
  minimum and divides by the maximum (unless zero).
- ml/model.py defines a 63-input PyTorch classifier. app.py applies softmax
  and returns the maximum class and score. That score is a model probability,
  not verified/calibrated confidence.
- README claims 26 A-Z labels. ml/convert.py derives sorted one-character
  alphabet labels from dataset folders. J and Z are listed as classes, but
  the pipeline classifies a single frame of static landmarks; reliable
  motion-dependent J/Z behavior is not established.
- app.py appends a prediction after 20 stable frames. It has no neutral-pose
  release re-arming, so a held pose may append repeatedly. Its UI displays a
  probability but does not gate acceptance on a threshold.
- requirements.txt lists torch, torchvision, mediapipe, opencv-python, numpy,
  matplotlib, joblib, tqdm, flask, and flask-cors without version pins.
- Inference command from the repository root: python app.py. On macOS/Linux,
  the usual isolated setup is:
    python3 -m venv .venv
    source .venv/bin/activate
    python -m pip install -r requirements.txt
    python app.py

Local verification status:
- Upstream requirements installed into an isolated Python 3.12 virtual
  environment outside the project. No dependencies were added to the static
  website.
- Confirmed the saved model loads, the MediaPipe detector initializes, and
  the local camera supplies frames.
- Tested a live C handshape. The detector found a hand; the classifier
  predicted C with a raw softmax score of 0.9990 at the 21st consecutive
  frame, crossing the upstream 20-frame threshold. The frame was processed
  locally and not saved.
- This verifies one static handshape only. It does not validate all letters,
  probability calibration, general accuracy, or motion-dependent J/Z.

Checkpoint: model setup and one live static-letter inference work locally.
The user chose browser-local inference; ASL inference frames and landmarks are
not sent to the game server. Optional live video is a separate explicit
peer-to-peer share, and is never relayed or stored by the game server. The
browser-local path also predicted and accepted C from the camera, then required
hand release before re-arming. Test more static letters and investigate the
motion-dependent J/Z limits before claiming broader recognition support.

Step 2 - Integrate browser-local inference (complete)
-----------------------------------------------------
The user selected browser-local inference. An ONNX export of the
upstream PyTorch classifier (320,660 bytes) matched PyTorch for 8 test vectors
(maximum logit absolute error 5.72e-6, zero predicted-class mismatches).
ONNX Runtime Web also loaded that export in a browser and returned 26 logits.
This verifies classifier conversion/runtime. The local static site also
verified browser MediaPipe capture, prediction confirmation, and release
re-arming with a live C handshape.

No upstream LICENSE file was found in the checked-out repository. The user
confirmed permission to bundle the classifier. The MediaPipe hand-landmarker
asset remains loaded from its publisher's hosted location and was not copied.
Browser-local inference is integrated: MediaPipe hand landmarks use the
upstream normalization, then the ONNX classifier; predictions require explicit
confirmation and the hand must be released before re-arming. Camera frames
and landmarks are not sent to a server. The simulation remains available and
clearly labeled.

Step 3 - Build one real multiplayer game loop (complete)
---------------------------------------------------------
Create/join a room for exactly two players; synchronize room members, turn
ownership, prediction confirmation/retry, and accepted letters through the
WebSocket server. ASL inference remains local; players can separately opt into
peer-to-peer video. The UI provides an invite link and room-code flow.
Checkpoint: two WebSocket clients join and receive the same authoritative
letters and alternating turns. Live camera streaming requires both players to
grant camera access and may not connect on restrictive networks without TURN.

Step 4 - Add validated words, score, and timer (complete)
----------------------------------------------------------
The server validates the six-word cycle, runs a server-authoritative
two-minute round, awards team score toward 500, and deduplicates action IDs.
Reconnect tokens restore a player's seat; disconnected rounds pause until
players reconnect. `npm test` verifies room creation/joining, turn enforcement,
duplicate action handling, shared letter updates, and reaching 500 points.
Timer expiry and browser reconnect still need broader dedicated coverage.

Verify actual Muse Image access, endpoint, and credentials before integration.

Step 6 - Add communication
--------------------------
Add real-time text chat. Add optional speech transcription only if a supported

Checkpoint: chat works and the game remains playable without a microphone.

Step 7 - Add results and sharing
--------------------------------
Show accurate round statistics and implement only a verified, user-initiated
sharing flow. Do not assume direct Facebook timeline publishing is allowed.
Checkpoint: results are accurate and sharing excludes webcam footage/private
chat and requires an explicit action.

Step 8 - Polish and test
------------------------
Match the reference style, check mobile layouts and keyboard accessibility,
and test camera denial, hand loss, low confidence, disconnect/reconnect,
generation failures, and timer expiry. Document setup and known limitations.
Checkpoint: the README acceptance tests are covered without pretending
unavailable services work.

Demo scope (current)
--------------------
`npm start` serves the website and WebSocket room server. Two browser clients
can create/join a room, take turns confirming letters, and share server-
validated words, score, and a two-minute timer. Room state is in memory, so a
server restart clears active games. ASL inference permission is requested
after a player selects Enable local ASL recognition. Live video sharing is
separate and opt-in; video goes peer-to-peer after both players enable sharing.
The simulation control remains clearly labeled. Image generation is
illustrative only; chat and social sharing are not implemented.
